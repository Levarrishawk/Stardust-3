## WHY THESE TWO ROUNDS ARE ONE ROUND

H(a) writes loot groups that hand out 23 SoM weapon templates. H(b) is what registers those
23 server templates. Without H(b), every one of the 23 resolves to nil at create time and the
loot roll silently drops the item.

Proof, generated by walking the real include closure from `object/serverobjects.lua`
(25,782 files, 24,633 registered templates): **23 of the 44 templates H(a) needs are NOT in the
closure.** All 23 are weapons. All 21 non-weapons are already loaded.

## PART 1 — H(a) STEP 1: 50 loot item files

Create `loot/items/mustafar/<name>.lua`, one file per row below.

### The file shape — copy it exactly from the one that already ships

`loot/items/mustafar/cube_loot_3r.lua` is the pattern:

```lua
cube_loot_3r = {
	minimumLevel = 0,
	maximumLevel = -1,
	customObjectName = "",
	directObjectTemplate = "object/tangible/loot/mustafar/cube/loot/cube_loot_3r.iff",
	craftingValues = {},
	customizationStringNames = {},
	customizationValues = {}
}

addLootItemTemplate("cube_loot_3r", cube_loot_3r)
```

Rules that apply to all 50:

- `minimumLevel = 0`, `maximumLevel = -1` on every file. Live's tier column is recorded in the
  header comment as provenance; it is **not** turned into a level gate. Inventing a gate would
  change drop behaviour on data live does not supply.
- `craftingValues = {}`, `customizationStringNames = {}`, `customizationValues = {}` on every
  file. The object template already carries the item's base stats. Do not author stat rolls.
- `customObjectName` is exactly the string in the table below, including the quotes shown. Where
  the table shows `""`, the shipped STF name is used — that is deliberate, same as `cube_loot_3r`.
- Tabs for indentation, matching the file above.
- **ASCII only.** No smart quotes, no em dashes, no accented characters. Anywhere.
